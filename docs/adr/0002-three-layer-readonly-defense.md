# 只读保障用三层防御，守卫是正向 AST 白名单而非黑名单

对源库的任何 SQL 都要过三层：① sqlglot 解析成 AST 后**只允许白名单节点**，重生成时 `comments=False`
且拒绝 hint 注释；② 交给源引擎 `EXPLAIN` dry-run；③ 会话级只读 + 语句超时 + 行数上限。

**为什么**：黑名单永远漏（新语法、注释绕过、多语句、CTE 里藏 DML），而源库是别人的生产数据，
漏一次的代价不可接受。正向白名单可以形式上说清"允许什么"，也因此能当测试 oracle——攻击语料即断言。
`comments=False` 是重生成不变式：不关掉注释，`/*+ */` 这类引擎指令就会随重生成溜进源库。

## 补记一（P5-036）：上面最后那句因果对 MySQL 是错的，结论不动

MySQL 的 `/*+ … */` 在 sqlglot 的树上不是注释而是 `exp.Hint`（`args["hint"]`），`comments=False`
**剥不掉它**，它会原样穿过重生成被源库真执行。真正挡住它的是解析前那发**方言无关**的裸文本判定
（检测到 hint 直接拒），所以"拒绝 hint"这条决策的依据从"重生成会丢它"换成"它会被真执行"——
后者比前者更强，结论一字未改。细节与实测见 `docs/nl2sql-safety.md` §2。

## 补记二（P5-037）：第 ② 层落地了，但它的**位置**与**尺子**都不是本文当初的写法

- **位置**：②不住在守卫里。`guard()` 不碰库，而 `EXPLAIN` 必须在真源库连接、第三层那条只读会话建好之后
  才能发，所以它落成独立模块 `app/services/nl2sql/dry_run.py`。**分家不是洁癖**：本 ADR 的立论是
  "三层各自独立有效"，而这句要能被测出来，前提是第二层能单独关掉、单独反证
  （`dry_run=False` 时断"源库一条 `EXPLAIN` 都没收到"）。塞进守卫它就只是三层里的一段代码。
- **尺子取"逐行 `rows` 的最大值"，不是乘积也不是求和**：`EXPLAIN` 的 `UNION` 两臂是并列的两次扫描，
  按乘积算实测会把一条合法问句（30226×87912）判成超阈值。这一格是引擎**估算**不是真行数，
  所以 ② 是**代价闸门**不是正确性闸门——它关掉时 ①③ 的判定一字不变。
- **读不出来 ≠ 一律拒**：`SELECT count(*) FROM t` 这种裸聚合，`EXPLAIN` 的 `rows` 给 `NULL` 而 `Extra`
  写着 `Select tables optimized away`——引擎在**自证它不扫表**。按"读不出来就按最严一档"的原始写法，
  第二层专门拦的是最便宜的那种计划。现在的分档（全 `NULL` 才算读不出来、每行都自证 optimized away 则放行）
  与实测见 `docs/nl2sql-safety.md` §3.2。
- **顺带一条归因更正**：本文当初把笛卡尔积挂在 ②，实测它属 ①（逗号连接在 AST 上可见，
  且与"显式 `JOIN` 不写 `ON`"逐字同形），见 §3.4 与 §1.2 ⑥.1。

## 补记三（P5-041）：**哪一层有权触发回喂**是一条编排规则，不是一句常识

补记二定了 ② 的位置，但没说清两件更贵的事。它们到 036/038 才成为实物，而本文的正文（"三层彼此独立"）
单独读会给出**相反**的答案：

- **② 的输入是 `sql_final`，不是模型原文**。① 会钳位 LIMIT（补 `+1` 探针）、剥围栏与尾随 `;`；
  把模型那棵 AST 直接喂 `EXPLAIN`，等于试算一条**我们并不打算执行**的语句，① 出口那条运行期自校验
  （§1.3 的不动点）也就没有对象可比。所以 ② 只能站在 ① 之后，这条"顺序"是承重结构不是风格。
- **只有 ② 拒的那一支回喂，① 拒的绝不回喂**（§3.5 的两条收窄，封顶 1 次写死成常量、不开键）。
  ① 的拒绝（越权表／多语句／DML）重试一百次还是错的，而回喂它们等于把表白名单告诉模型、再骗它绕一次。
  于是"三层各自独立"在编排这一层要延伸成一句更强的话：**三层共用同一枚 `GuardRuleId` 词表（§1.1.1），
  但只有第二层那一支有权触发第二次生成**。
- **③ 那一支今天不回喂，是认下的取舍不是漏做**。源库执行期炸出来的是 `SQLAlchemyError`／`QueryTimeout`，
  不是 `SqlGuardError`；要接住它就得把 011 定的"真故障原样上抛"改成"早退 + 回喂"，roadmap 没要这一条。
  代价一并写在面上：真到执行那一刻才暴露的那一类（源库权限、引擎侧函数缺失、超时）**今天救不回来**。
  为什么这不算漏掉目标场景——列名拼错／表名记混在 `EXPLAIN` 当场就被拒（实测 `1054`/`1146`），
  它们在 ② 就已经是那句源库原话了。

**为什么这三条占本 ADR 的一条补记而不只住在 safety**：它难逆（一旦给 ① 也加回喂，
`chat_messages.guard_result.retries[]` 的语义就变成"模型曾被告知越权对象清单"，那是安全事件不是重试）；
无上下文会困惑（今天读 `pipeline` 只看到一支 `except SqlGuardError`，看不出为什么另外两支不在这里）；
有真实取舍（上面第三条就是那个被放弃的选项）。实现细节与用例住 `docs/nl2sql-safety.md` §3.5 与 §3.7。
